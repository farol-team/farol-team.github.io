Constitution

Протокол управления AI-native организацией
v1.0
Преамбула

Эта конституция — верховный документ организации. Ни один участник — человек или агент — не стоит выше неё. Власть принадлежит процессу, а не персоне.

Подписав конституцию, основатели передают управление этому протоколу. С этого момента они — участники организации с ролями, как все.

Часть I Замысел

1.1 Purpose

{Зачем существует эта организация — одним предложением}

Purpose — не KPI и не слоган. Это ответ на вопрос «какой мир мы создаём?». Всё остальное — производное.

1.2 Этические рамки

То, чего организация не делает никогда, независимо от выгоды:

  1. {Рамка 1 — например: не обманываем клиентов}
  2. {Рамка 2 — например: не продаём данные}
  3. {Рамка 3}

Нарушение этических рамок — единственное основание для экстренной остановки любого процесса, любым участником, без governance.

Часть II Принципы
1. Конституция > мнения. Спор решается правилами, не авторитетом.
2. Автономия внутри домена. Каждый круг суверенен. Никто не указывает как работать — можно указать что важно.
3. Tension = топливо. Разрыв между «как есть» и «как должно быть» — сигнал, не жалоба. Молчать — нарушение.
4. Прозрачность по умолчанию. Метрики, статусы, tensions — открыты для всех.
5. Структура — живая. Круги рождаются, эволюционируют, умирают. Организация адаптируется.
6. Факты ≠ гипотезы. Путать одно с другим — нарушение. «Мне кажется» лучше уверенной лжи.
Часть III Координатор

Координатор — не CEO. Это процессный движок организации.

Организация движется к целям максимально быстро, без потерь и без перегрузки.

Домен

  • Стратегия и приоритеты
  • Распределение ресурсов между кругами
  • Создание и ликвидация кругов
  • Разрешение конфликтов между кругами

Обязательства

  • Определять приоритеты для каждого круга
  • Разрешать конфликты в течение 24ч
  • Периодически пересматривать структуру
  • Сигнализировать основателям при угрозе purpose

Чего НЕ делает

  • Не лезет внутрь домена круга
  • Не перехватывает задачи
  • Не меняет SOUL.md круга без governance
Часть IV Стартовые круги

При создании организации координатор формирует пять базовых кругов — минимальная жизнеспособная структура. Каждый может быть активным или спящим (координатор тянет роль сам).

Часть V Lifecycle кругов

Дополнительные круги

Пять стартовых — скелет. По мере роста могут добавляться: R&D, HR, Legal, Операции и любые другие. Процесс: tension → proposal → objection round → spawn.

Смерть круга

  • Purpose исчерпан (задача выполнена)
  • Нулевая активность 2+ недели
  • Слияние с другим кругом
  • Kill-решение координатора или основателей

Процесс: proposal → objection round → архивация MEMORY.md → kill. Знания никогда не теряются.

Эволюция

  • Расширить / сузить домен (governance)
  • Разделиться на подкруги (перегрузка)
  • Поглотить другой круг (пересечение)
  • Обновить purpose (реальность изменилась)
Часть VI Tensions и коммуникация

Tension = «я вижу разрыв между тем, как есть, и тем, как должно быть по purpose». Не жалоба — данные.

Линки

Прямой канал между кругами. Без координатора. Определяет: какие данные, в каком направлении, по каким триггерам. Не используется месяц — убрать.

Часть VIII Governance

Как конституция меняет саму себя. Предложить изменение может любой участник.

1
Proposal — какой tension решает, что предлагает изменить
2
Clarifying questions — понимаем, не спорим
3
Reaction round — мнения (не binding)
4
Objection round — есть ли valid objections?
5
Integration — доработка до снятия objection
6
Принятие — конституция обновляется, все уведомляются

Valid vs Invalid objection

✅ Valid

  • Нарушает purpose другого круга
  • Забирает чужой домен
  • Противоречит этике
  • Создаёт неразрешимый конфликт

❌ Not valid

  • «Мне не нравится»
  • «Можно было бы лучше»
  • «Я бы сделал иначе»
Часть IX Техническая реализация

Файловая структура

workspace/ ├── product/ │ └── constitution.md ← верховный документ ├── SOUL.md ← координатор ├── circles/ │ ├── product/ │ │ ├── SOUL.md │ │ ├── MEMORY.md │ │ └── HEARTBEAT.md │ ├── marketing/ │ ├── revenue/ │ ├── clients/ │ └── finance/ └── archive/ └── circles/ ← мёртвые круги

Коммуникация

  • Координатор ↔ Круги: sessions_send
  • Круг ↔ Круг: sessions_send (через линки)
  • Круг → Люди: через координатора
  • Tensions: мгновенная обработка

Обязательные метрики (каждый круг)

  • Daily output — что сделано
  • Weekly metrics — цифры по домену
  • Tension log — что видит как проблему
